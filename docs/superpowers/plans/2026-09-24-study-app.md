# Study App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `study-app/`, a static local web app that turns the Module 1 and Module 2 lesson notes into refreshers, simulations, scenario questions, and a small game layer.

**Architecture:** Pure TypeScript engine (`src/engine`) and simulation math (`src/sims/*/model.ts`) are unit-tested with Vitest and know nothing about React. Content is typed data (`content/module-XX/*.ts`) validated by a pure validator that `npm run check` runs from a CLI script. The React shell (`src/shell`) renders modules, lessons, sims, and rounds, and persists progress through a storage adapter over `localStorage`.

**Tech Stack:** Vite, React, TypeScript, Vitest, tsx (for the check script). No backend, no router library, no UI library.

**Spec:** `docs/superpowers/specs/2026-09-24-study-app-design.md`

## Global Constraints

- Lives at `study-app/`; Vite + React + TypeScript; static build; no backend.
- Progress stays in the browser (`localStorage`), with JSON export and import. Unparseable stored progress is backed up, reset, and reported to the user instead of crashing.
- The repository is public: no course transcript or page text. Content is paraphrased and within course scope; anything beyond the course is labeled.
- Prices are "illustrative example values, not AWS quotes (course maximum discounts, 2026-09-24)".
- XP: 10 for a correct first attempt, 5 when correct after the hint, 0 after the explanation is shown.
- Weak spots: missed concepts return after 1, 3, and 7 days. Correct advances; passing the 7-day step clears; wrong restarts at 1 day.
- Module badge: when every lesson challenge in the module is cleared (a module with locked lessons cannot be complete yet).
- One boss round (multi-step incident) per module.
- Module 2 v1 scope: lessons 1–5 only. Scaling, ELB, and messaging lessons are shown as locked; their sims are not built.
- `npm run check` fails on: missing hint or explanation, duplicate IDs, unknown concept tags, unresolved note links.
- Invalid content fails the build (`npm run build` runs the check first).
- Running locally costs $0.

## Core Types (`src/engine/types.ts`)

```ts
export type QuestionType = 'single' | 'multi';
export interface Option { id: string; text: string }
export interface Question {
  id: string; type: QuestionType; prompt: string; options: Option[];
  answer: string[]; hint: string; explanation: string; concepts: string[];
  beyondCourse?: boolean;           // labeled in the UI
}
export interface SimRef { id: SimId; config?: Record<string, unknown> }
export type SimId = 'pricing' | 'global-infra' | 'shared-responsibility' | 'instance-matcher';
export interface Lesson {
  id: string; module: string; order: number; title: string;
  note: string;                     // path relative to study-app/, e.g. ../AWS-Cloud-Practitioner/...
  keyIdea: string[];                // 3–5 lines
  sim?: SimRef; questions: Question[];
}
export interface LockedLesson { order: number; title: string; reason: string }
export interface BossRound { id: string; module: string; title: string; scenario: string; steps: Question[] }
export interface Module { id: string; number: number; title: string; lessons: Lesson[]; locked: LockedLesson[]; boss: BossRound }
```

### Task 2: Answer checking and XP (TDD)

**Produces:** `checkAnswer(q: Question, selected: string[]): boolean`; `type Stage = 'fresh' | 'hinted' | 'revealed'`; `nextStage(stage, correct): Stage`; `xpFor(stage): 10 | 5 | 0`.

- [ ] Implement, run, commit: "Add answer checking and XP rules".

### Task 3: Weak-spot scheduling (TDD)

**Produces:** `INTERVAL_DAYS = [1, 3, 7]`; `type WeakSpot = { step: 0 | 1 | 2; due: string }` keyed by concept; `recordMiss(spots, concepts, now)`; `recordWeakSpotResult(spots, concept, correct, now)`; `dueConcepts(spots, now)`; `pickWeakSpotQuestions(spots, questions, now)`.

- [ ] Failing tests: a miss schedules each concept at step 0, due now + 1 day; a correct answer at step 0 → step 1 due + 3 days; step 1 → step 2 due + 7 days; correct at step 2 removes the concept; wrong at any step → step 0 due + 1 day; a new miss on a tracked concept resets it to step 0; concepts not yet due are excluded; one question is picked per due concept and the pick rotates with the step.
- [ ] Implement, run, commit: "Add weak-spot scheduling".

### Task 4: Progress, badges, storage (TDD)

**Produces:** `Progress = { version: 1; xp; questions: Record<id, { cleared: boolean; xp: number; misses: number }>; weakSpots; mistakes: { questionId; concepts; at }[]; }`; `emptyProgress()`; `recordChallengeResult(progress, question, stage, correct, now)`; `isModuleComplete(module, progress)`; `earnedBadges(modules, progress)`; `loadProgress(storage, now) => { progress; notice?: string }`; `saveProgress`; `exportProgress`; `importProgress(json): Progress` (throws on invalid).

- [ ] Failing tests: XP is awarded once per question (replaying a cleared question adds 0); first wrong answer logs a mistake and schedules weak spots; a module with locked lessons is never complete; a module whose lessons and boss steps are all cleared is complete and earns its badge; corrupted JSON is copied to a `…backup…` key, progress resets, and a notice is returned; valid JSON round-trips through export/import; import rejects wrong shapes.

### Task 6: Simulation models (TDD)

- **Pricing** (`src/sims/pricing/model.ts`): `EXAMPLE_ON_DEMAND_HOURLY = 0.10`; discounts Savings Plans 0.72, Reserved Instances 0.75, Spot 0.90; usage patterns as hourly profiles `{ instances, hours }[]` summing to 8,760 h (steady 24/7, business hours, spiky, interruptible batch, unknown/new). `yearlyCosts(pattern, committedInstances, rate)` returns per-option `{ cost, wastedCommittedHours, suitable, caveats }`. Commitment math: committed instances × 8,760 h at the discounted rate, plus uncovered instance-hours at On-Demand. Spot = used hours × rate × 0.10, unsuitable unless interruptible. Dedicated Hosts/Instances are listed with no price (none captured) and a when-to-use note. Tests: exact yearly figures for steady and business-hours patterns, waste for over-commitment, Spot unsuitable for non-interruptible patterns, cheapest suitable option.
- **Global infra:** `survives(deployment: { region; az }[], outage)` for AZ and Region outages.
- **Shared responsibility:** `scoreAssignments(items, service, assignments)`.
- **Instance matcher:** `gradeMatches(workloads, picks)`.
- [ ] Tests first for each, then implementation. Commit: "Add simulation models".
